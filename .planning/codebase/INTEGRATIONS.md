# External Integrations

**Analysis Date:** 2026-05-20

## Git Hosting

**Primary remote (`origin`, dual-push):**
- Fetch URL: `ssh://git@git.corpus.intra:7999/cs-offensivesecurity/penskillz.git` (Corpus internal Bitbucket / git server).
- Push URL #1: `git@github.com:suculent/penskillz.git` (GitHub public mirror).
- Push URL #2: `ssh://git@git.corpus.intra:7999/cs-offensivesecurity/penskillz.git`.
- Configured via `git remote set-url --add --push origin <url>` so a single `git push origin` writes to both hosts. Fetch still resolves to Corpus only — GitHub is push-only on `origin`.

**Secondary remote (`github`):**
- Fetch + push: `git@github.com:suculent/penskillz.git`.
- Used as an explicit fallback / verification target when bypassing the dual-push.

**Install URL (default):**
- `install.sh:21` defaults `REPO_URL` to `https://github.com/suculent/penskillz.git`. Overridable with `PENSKILLZ_REPO=…` or `--repo …`.

Each submodule is declared in both `.gitmodules` and `sources.yaml`. `penskillz sync` (`bin/penskillz`) drives `git submodule update --init --recursive --depth 1`. Only `strix` declares `shallow = true` in `.gitmodules`; the rest rely on the installer's `--depth 1` flag.

License metadata is propagated from `sources.yaml` (`license:` SPDX id) into the extracted `SKILL.md` frontmatter so downstream agents can surface upstream license terms.

## Agent Skill Directories

Defined in `bin/penskillz:46-50` (`AGENT_TARGETS`). Each agent has an env override and a default path:

| Agent | Flag | Default path | Env override |
|-------|------|--------------|--------------|
| Claude Code | `--agent claude-code` (default) | `~/.claude/skills/` | `CLAUDE_SKILLS_DIR` |
| Codex | `--agent codex` | `~/.codex/skills/` | `CODEX_SKILLS_DIR` |
| Qwen Code | `--agent qwen` | `~/.qwen/skills/` | `QWEN_SKILLS_DIR` |

`--agent all` installs into every detected directory. Install prefix can be overridden globally with `PENSKILLZ_PREFIX`. Installation is a `shutil.copytree`-style copy from `dist/skills/` into the target directory.

## Package Registries

**PyPI (lazy, optional):**
- `install.sh:36` runs `python3 -m pip install --user --quiet pyyaml` only when `import yaml` fails.
- No private index, no `--index-url`, no pinning. Failure is non-fatal: GTFOBins/LOLBAS extraction is skipped and the rest continues.

## Shell Integration

`install.sh:73-83` appends `export PATH="$HOME/.penskillz/bin:$PATH"` to `~/.zshrc` and `~/.bashrc` when not already present. Idempotent — guarded by `grep -qsF '/.penskillz/bin'`.

## Planned: Husky / pre-commit Hook (Node-based)

The next integration to be added is a Node-managed pre-commit hook layer using **husky** (and optionally **lint-staged**), installed into this repo as a dev workflow concern:

- New files expected: `package.json` (devDependencies: `husky`, plus an optional formatter such as `lint-staged` or `prettier`), `.husky/pre-commit`, and possibly `.husky/_/husky.sh` (autogenerated).
- `package.json` will declare a `prepare` script (`husky` or `husky install`) so `npm install` activates the hooks. No runtime Node dependency for end-users — this is dev-only.
- The hook will run lightweight checks before commit: at minimum a `python3 -m py_compile bin/penskillz lib/**/*.py` sanity pass and a `git diff --check` whitespace guard. A YAML lint of `sources.yaml` is a likely addition.
- **Does not** install pre-commit hooks into the upstream submodule clones — those each ship their own (`sources/strix/.pre-commit-config.yaml` is the upstream's own, ignored here).
- Adds a new platform requirement at commit time only: Node.js + npm. End-users running `install.sh` are unaffected.

When this lands, update `STACK.md` to list Node/npm as a dev-time dependency and document the `prepare` script flow.

## What This Project Does NOT Integrate With

- No databases, no cache services, no message brokers.
- No HTTP APIs at runtime. The only network access is `git clone` / `git pull` against the submodule remotes and (optionally) one `pip install` for PyYAML.
- No telemetry, error tracking, or CI service is currently wired in. No `.github/workflows/` at the repo root.
- No webhooks, inbound or outbound.
- No secrets management — there are no API keys, tokens, or `.env` files. All auth is SSH-key based against the two git remotes.
